# Phase 2 — UI Design Contract

> Visual + interaction contract for Phase 2 iPad polish + black-key visibility fix. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope is deliberately narrow.** Only two visible changes ship this phase:
> 1. Black-key fill + top-edge highlight (D-10)
> 2. iPad touch ergonomics pass (D-08)
>
> All other tokens below are *codification of the existing state* — locked, not refactored. Anything outside these two items is scope creep and belongs to a later phase.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled CSS, no component library) |
| Preset | not applicable |
| Component library | none (Svelte 5 components, scoped styles) |
| Icon library | none (text-only controls) |
| Font | `system-ui` (do NOT change) |

**Rationale.** Jay-6 is a single-page touch instrument, not a CRUD UI. shadcn / Radix / icon libraries add zero value here and would bloat the deploy footprint. Existing styling pattern (Svelte `<style>` blocks with raw CSS) stays.

## Spacing Scale

| Token | Value | On-grid? | Usage |
|-------|-------|----------|-------|
| 4xs   | 0.25rem (4px)  | yes | Tightest inline gaps |
| 3xs   | 0.5rem (8px)   | yes | Compact element spacing |

| md    | 2rem (32px)    | yes | Layout gaps |

**Exceptions / known debt:**
- `0.75rem` is off the 8-point grid. **Active in current code; not refactored this phase.** Document as known debt for a later typography/spacing pass.
- Touch-target min size: **44×44 CSS px** on iPad (Apple HIG override, mandatory — see Interaction Contract).

## Typography

Existing system — **locked as-is for Phase 2**, not refactored:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (1rem) | 400 | 1.5 | Default text |

**Known debt (NOT in scope this phase):** the existing CSS uses ~8 distinct font-sizes across components, which is more than the canonical 3–4. A typography consolidation pass is recommended for a future phase. Phase 2 leaves it alone — touching it risks breaking the J-6 visual identity mid-ship.

Font family: `system-ui` everywhere. Do not introduce a custom webfont.

## Color

### Locked palette (codified, not changed)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111` | App background |
| Secondary (30%) | `#1a1a1a` (TopBar), `#181818` (piano frame), `#2a2a2a` (control bg) | Surfaces, frames, controls |
| Control border | `#3a3a3a` | Dropdown / button borders |
| White-pad cream | `#f4f1ea` | White piano-key faces (J-6 identity) |
| Accent (10%) — J-6 orange | `#ff7a1a` | **Reserved-for list below** |
| Text primary | `#eee` | Default readable text |
| Text labels | `#888` | Secondary labels |
| Text footer | `#666` | Footer / muted text |

### Accent reserved for (explicit list — never used elsewhere)

1. **Held / active pad highlight** on white keys (pressed state)
2. **Held / active pad highlight** on black keys (pressed state)
3. **Black-key fallback border** (option C in fallback ladder only — see below)

J-6 orange is **never** used for: TopBar control fills, focus rings, hover states, dropdown highlights, body text, link styling. Reserving it strictly to "this key is currently sounding" preserves its function as a status signal, not decoration.

### Black-key visibility fix (D-10) — selected treatment

**Selected: Option B — lift fill + top-edge highlight.**

| Property | Value |
|----------|-------|
| Black-key fill | `#2e2e2e` (was `#1f1f1f` — lifted ~9 RGB points for visibility against `#181818` frame) |
| Black-key top-edge highlight | `box-shadow: inset 0 1px 0 rgba(255,255,255,0.08)` (1px inner highlight on top edge only) |
| Piano frame (context) | `#181818` (unchanged) |
| White-pad fill (context) | `#f4f1ea` (unchanged) |
| Held/active pad orange (context) | `#ff7a1a` (unchanged) |

**Design intent.** The 1px inset highlight reads as a subtle bevel — a Teenage Engineering pocket-operator "physical control" vibe. Lifts the black key off the frame without resorting to a colored border (which would compete with the J-6 orange held-pad signal).

### Fallback ladder (executor pivot path)

If the executed Option B doesn't read well in the real browser/iPad render, executor may pivot down this ladder **without re-invoking `/gsd:ui-phase`**:

| Step | Option | Treatment | When to use |
|------|--------|-----------|-------------|
| 1 (default) | **B** | Fill `#2e2e2e` + inset 1px top highlight `rgba(255,255,255,0.08)` | Selected — try this first |
| 2 | A | Fill `#2e2e2e`, no highlight | If the highlight reads as a defect / "stuck pixel" on Retina |
| 3 | C | Fill `#1f1f1f` + 1px hairline border `rgba(255,122,26,0.35)` | If lifting fill makes black keys look gray (loss of identity). Note: this is the only sanctioned secondary use of accent orange. |
| 4 | D | Fill unchanged + drop piano frame to `#000` | Nuclear option. Changes the frame, not the key — preserves key identity at cost of frame contrast against `#111` app bg. |

**Decision rule for executor.** Try step 1 in the running app on both desktop Chrome and the iPad target (Web MIDI Browser). If it reads correctly on both, ship. If not, walk the ladder one step at a time, re-check, ship the first acceptable step. Document which step shipped in the verify-phase notes.

## Interaction Contract (iPad touch ergonomics — D-08)

This section is the **iPad ergonomics contract**. Every interactive element in the app must satisfy these rules. Desktop behavior is unchanged.

### CSS contract (mechanical)

| Rule | Applies to | Value | Why |
|------|-----------|-------|-----|
| `user-select: none` | TopBar root + all dropdown components | mandatory | Mirror existing `PianoLayout.svelte` pattern. Prevents text-selection flash on long press. |
| `touch-action: manipulation` | every `<button>`, `<select>`, dropdown trigger, pad | mandatory | Kills the 300ms tap delay AND kills double-tap zoom on controls. Standard iOS web-app fix. |
| Min tap target | every interactive element | **44×44 CSS px** | Apple HIG. Use `min-width` + `min-height`; padding alone is not enough if the visual element is smaller. |
| `overflow: hidden; position: fixed` on `html, body` | iPad media query only | mandatory | Prevents rubber-band scroll / address-bar jitter during pad presses. Desktop unaffected. |
| iPad media query | `@media (pointer: coarse) and (max-width: 1366px)` | use this guard | Targets iPad in Web MIDI Browser without breaking desktop touch laptops with mice. |

### Visual contract (touch feedback)

iOS `:hover` is unreliable on touch (sticky after tap-release). Every interactive control must therefore have a **`:active` state** as the touch substitute.

| Control type | `:active` treatment |
|--------------|--------------------|
| TopBar buttons (Int/Ext, Latch, Panic, etc.) | brightness bump: `filter: brightness(1.15)` OR background lighten one step (e.g., `#2a2a2a` → `#3a3a3a`) |
| Dropdown triggers | same as TopBar buttons |
| Pads (already implemented in Phase 1) | held = J-6 orange `#ff7a1a` — **already correct, do not change** |
| Transpose `±`, `Z`/`X`, latch toggle | brightness bump OR a 2–3% scale-down (`transform: scale(0.97)`) for tactile feedback |

**Active-state duration.** Native `:active` only — no JS-driven timeouts. Let the browser handle press/release.

**No hover-only affordances.** Anything that was previously "appears on hover" must either be always-visible or moved to an explicit tap.

## Copywriting Contract

Jay-6 is a hardware-style instrument. Copy is minimal by design — most controls are unlabeled or use single-letter / symbol labels (`±`, `Z`, `X`, Int/Ext). **No new copy is introduced in Phase 2's UI work.** (User-facing copy for the new MANUAL.md is a separate deliverable, not governed by this UI-SPEC.)

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA | n/a — no CTA pattern in this app | Pads ARE the primary interaction; they're not buttons with labels |
| Empty state | n/a — app has no empty states (banks always loaded from JSON) | |
| Error state — MIDI permission denied | existing copy unchanged this phase | Owned by Phase 1 / setup UX |
| Error state — no MIDI device | existing copy unchanged this phase | |
| Destructive confirmation — Panic button | existing — no confirmation (panic IS the recovery action) | Locked: panic must remain one-tap, instant. Adding a confirm would defeat the purpose. |
