## Critical Issues

### CR-01: [BLOCKER] Global Space shortcut hijacks focused controls

**File:** `src/App.svelte:132`

**Issue:** `onKeyDown` only excludes `INPUT`, `SELECT`, and `TEXTAREA` targets before handling app shortcuts. The redesign adds many real buttons in `TopBar.svelte` and `VariationPicker.svelte`, but when any button has focus, pressing Space is still captured by the app-level handler at lines 143-166. That calls `preventDefault()` and toggles latch instead of activating the focused button. Keyboard users cannot Space-activate setup, variation, transpose, clock, bank, or latch controls; worse, trying to activate a focused control can unexpectedly change the latch state during playback.

**Fix:**

```ts
function isEditableOrControlTarget(target: EventTarget | null): boolean {
  const element = target instanceof HTMLElement ? target : null;
  return Boolean(
    element?.closest(
      'input, select, textarea, button, [contenteditable="true"], [role="button"], [role="switch"], [role="menuitem"]',
    ),
  );
}

function onKeyDown(ev: KeyboardEvent): void {
  if (isEditableOrControlTarget(ev.target)) return;

  const k = ev.key.toLowerCase();
  // existing shortcut handling...
}
```

Add a focused-control regression test if/when component interaction tests exist: focus a variation/setup button, press Space, and assert latch does not toggle.

## Warnings

### WR-01: [WARNING] Pointer cancel/lost-capture release can still be skipped

**File:** `src/components/PianoLayout.svelte:55`

**Issue:** `endPress` deletes the captured pointer, then calls `releasePointerCapture` before `onRelease`. On cancellation/lost-capture paths, the browser may already have cleared capture or invalidated the pointer. If `releasePointerCapture` throws, execution never reaches `onRelease(k)`, leaving the host with a held pad and a stuck note/highlight. This is exactly the class of edge case the new pointer-capture logic is trying to close.

**Fix:**

```ts
function endPress(e: PointerEvent, k: Key) {
  if (captured.get(k) !== e.pointerId) return;
  captured.delete(k);
  e.preventDefault();

  const target = e.currentTarget as HTMLElement;
  if (target.hasPointerCapture?.(e.pointerId)) {
    target.releasePointerCapture(e.pointerId);
  }

  onRelease(k);
}
```

If real-device testing shows `hasPointerCapture` itself is not enough on cancellation paths, wrap only the release-capture call and still always call `onRelease(k)`.
