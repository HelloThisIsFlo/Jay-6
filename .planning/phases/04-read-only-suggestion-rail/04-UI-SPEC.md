# Phase 4 — UI Design Contract

> Visual and interaction contract for the read-only chord-chip suggestion rail. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Scope note:** Every value below is sourced from `04-CONTEXT.md` decisions D-01 through D-17 and the validated sketch CSS in `.agents/skills/sketch-findings-jay-6/sources/002-iphone-suggestion-rail/index.html` and `.../003-desktop-suggestion-rail/index.html`, cross-checked against `references/progressions.md`, `references/tokens.md`, and `references/topbar.md`. Nothing here is invented. One exception, made explicitly by the developer this pass: four sub-pixel sketch values (chip padding, chip internal gap, chip grid gap, iPhone panel collapse-control gap) were rounded onto the project's 4px grid rather than kept verbatim — see the Spacing Scale section below. Every other number is prescriptive, not a starting point.

**No exceptions — every declared value is a multiple of 4.**

The following values are pixel-level layout details, listed here for implementation reference (all on-grid, all derived from or equal to existing spacing tokens):

- Chip padding: `4px 8px` (`.chip`) — `xs` vertical, `sm` horizontal
- Chip internal gap (key ↔ name stack): `4px` (`xs`)
- Chip grid gap: `8px` (`.chips { gap: 8px }`, `sm`)
- Rail column grid: `column-gap 16px, row-gap 0` (`.cols { gap: 0 16px }`, `md`)
- Rail-head (eyebrow) gap: `8px` (`sm`), padding `0 4px 4px` (`xs`-based)
- iPhone panel header (`.p-head`) padding: `4px 8px 0 12px` (`xs`/`sm`-based, already on-grid)
- iPhone panel collapse control gap: `8px` (`sm`)

**Developer decision (this revision, supersedes prior sketch pixel values):** the validated sketch CSS used four sub-pixel values here — chip padding `5px 9px 6px`, chip internal gap `2px`, chip grid gap `6px`, iPhone panel collapse-control gap `6px`. The developer explicitly decided to round these onto the 4px grid instead of preserving the sketch's exact pixels ("don't care about one pixel, keep it simple"): `5px 9px 6px` → `4px 8px`, `2px` → `4px`, `6px` → `8px` (both chip grid gap and panel collapse gap). This intentionally supersedes the sketch precedent noted in earlier drafts of this spec. The remaining values above (`16px` column gap, `8px` rail-head gap, `4px`-based rail-head/panel-header padding) were already on-grid and are unchanged.

**Revision note (Dimension 4 fix, this pass):** the prior draft declared 6 distinct sizes (9/11/12/13/14/15px) against the "at most 4 sizes" contract. Two were free variables, not locked decisions, and were folded in:
- iPhone panel suggestion label (`.p-id .s-label`) was a raw-sketch-HTML artifact (`002-iphone-suggestion-rail/index.html` line 184, literal `15px`) never promoted into the validated `progressions.md` findings — folded into the same 14px (`--t-body`) used on desktop/iPad, so `.s-label` is one size everywhere.
- Chip key label (`.chip .k`) was 9px in raw sketch CSS but, like the label above, was never pinned to an exact px value in `progressions.md` (which only says "small pad key label," no size) or in `04-CONTEXT.md`. Folded onto the existing `--t-eyebrow` (11px/600/1.2) token already used for every other small-mono/metadata role in this rail (pager count, kind, eyebrow) — same weight and line-height as before, so only the size and its relationship to the pad's own 10px key label changes; the key remains visually smaller than the 14px chord name it sits beside, preserving the in-chip hierarchy. **Confirmed by the developer this revision:** 11px (`--t-eyebrow`) for the chip key label is final, not a placeholder.

The remaining 4 sizes are all locked and were kept as distinct values:
- **11px** — `--t-eyebrow` token (app-wide scale, `tokens.md`): eyebrow, kind, strip, panel collapse, pager, chip key.
- **12px** and **13px** — both explicitly required by **D-15** (`04-CONTEXT.md`, locked): "13px on desktop/iPad; 12px centred in the iPhone top bar." `progressions.md` repeats the same two-value split verbatim. Unifying these (the checker's suggested route) would contradict D-15, so the ≤4 target was reached instead by folding the two unlocked sizes (chip key, iPhone `.s-label`) above — no locked decision was touched.
- **14px** — `--t-body` token (app-wide scale) and the chip chord-name size explicitly locked in `progressions.md` ("mono 14px/600"); now also the suggestion-label size everywhere.

Total: 4 declared sizes (11/12/13/14px).

Eyebrow/label text (`SUGGESTIONS`, `Suggestions` strip, panel collapse) is authored as normal-case text (`Suggestions`) and rendered uppercase via `text-transform: uppercase` in CSS — do not author the string in caps.

Two weights only across the whole rail: **400** (kind metadata, pager count, empty state) and **600** (labels, eyebrows, chip text). No third weight.

## Color

Existing app-wide instrument palette (`tokens.md`, locked in Phase 02.1), applied to Phase 4 elements — this phase introduces no new colors:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg-0` `#0e0e0e` / `--bg-1` `#171717` | Page background; iPhone panel background |
| Secondary (30%) | `--bg-2` `#1f1f1f` (chip fill) / `--bg-4` `#3a3a3a` (chip border, dividers) | Chip chrome, rail/panel structural surfaces |
| Accent (10%) | `--accent` `#ff7a1a` | See reserved-for list below — **sounding only** |
| Destructive | not applicable | Phase 4 has zero destructive actions (read-only rail; a released held key is not a confirm-gated action) |

**Accent (`--accent`, orange) reserved for — nothing else:**
- The currently-pressed/held chip: `background: var(--accent); border-color: var(--accent); box-shadow: 0 0 14px 2px rgb(255 122 26 / .4)` — text and key color flip to `--bg-0`
- Soft echo on every *other* chip whose key is currently sounding (from a pad or another chip): `background: rgb(255 122 26 / .18); border-color: var(--accent)` — no glow, no text-color flip
- The paired lit pad underneath (existing pad behavior, unchanged by this phase)

Never orange for: default/idle chip fill or border, hover state, the eyebrow, kind metadata, the iPhone strip, or the panel chrome. A held chip's orange always wins over echo on that same chip — echo never overrides the actual press (D-03).

**Second semantic accent — steel (`--system`, `oklch(0.68 0.045 250)`)**, the app-wide "system status / metadata" color (already established, not introduced by this phase), reserved in Phase 4 for:
- Rail eyebrow (`SUGGESTIONS · N`)
- Kind metadata text (`progression` / `movement`)
- iPhone strip text, border-on-open (`aria-expanded="true"`), and chevron
- iPhone panel border-bottom and collapse-control text
- Focus-visible outline on the strip and panel nav buttons: `outline: 2px solid var(--system); outline-offset: 1px`

Steel never signals "sounding" — that is orange's exclusive job. Keeping the two accents apart is the same rule the rest of the app already follows.

**Cream key-color hint** (naturals only, `data-color="white"` chips): `border-color: rgb(244 241 234 / .6)`. Accidentals (`data-color="black"`) keep the default `--bg-4` border. This is the one sketch-tested variant ("cream outline") that was chosen; the alternate hint treatments (bottom lip, thick ring) were explicitly rejected — see "What to Avoid" in `references/progressions.md`.

## Layout Reference

**Desktop / iPad — inline columns under the pads (D-09):**
- Wraps in `<section class="rail" aria-label="Suggestions">`; eyebrow (`.rail-head`) above the columns
- Grid: `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))`, `gap: 0 16px` → 3 columns at iPad landscape width
- Each column: `.rail-id` (label + kind, stacked, 4px gap) above `.chips` (`grid-template-columns: repeat(var(--per), minmax(min-content, max-content))`, `gap: 8px`, `justify-content: start`)
- `--per` (chips per row) from the balanced-row formula: `rows = Math.ceil(n / 6); per = Math.ceil(n / rows)` — 7→4+3, 8→4+4 in the general case, though the catalogue cap (D-16/D-17) means a bank never actually exceeds 6
- Max 6 suggestions per bank (D-16/D-17): the iPad body-scroll lock (`pointer: coarse`, `max-width: 1366px`, `App.svelte`) means anything below the fold is unreachable — 3×2 exactly fills it

**iPhone landscape (`max-height: 480px`) — strip + anchored panel (D-10–D-13):**
- TopBar row 1 gains a `sugg` grid area between `pill` and `transpose`: `grid-template-areas: 'pill sugg transpose' 'bank style latch'` (extends the existing per-breakpoint pattern in `TopBar.svelte`)
- Strip (`.strip`): `min-height: 44px`, zero added height, centered in its zone, `Suggestions · N` + chevron (`▾` closed / `▴` open); empty bank replaces the strip with the 12px centered muted line, not a disabled button
- Panel (`.panel`): `position: absolute; top/left/right: 0`, nonmodal, anchored over the top bar only — `max-height` = the space above the pads, so it can never cover a pad; `border-bottom: 1px solid var(--system)`, `box-shadow: 0 8px 18px rgb(0 0 0 / .45)`, scrolls internally (`overflow-y: auto`) if content exceeds that space
- Panel shows exactly one suggestion at a time: header (`.p-head`, 44px min-height) = collapse control + `.p-id .s-label` (15px) + kind + pager (`‹ {i} of {n} ›`, step buttons 44×40 touch target, `.p-count` 11px mono tabular-nums) + × close (`aria-label="Close suggestions"`)
- Close via × / the collapse control in the panel header / Escape — never backdrop click (D-12)
- Page-index memory: stays on the current suggestion across close/reopen while the bank is unchanged; a bank change resets to `1 of N` (D-13)
- Accepted trade-off: bank / style / latch controls are hidden while the panel is open (D-12, deferred item)

**One chip component everywhere** (D-14): the same chip renders in desktop/iPad columns and the iPhone panel, both playable with soft echo — no separate "read-only" chip variant exists.

## Interaction State Reference

Chip visual states (D-03–D-08), in precedence order:

1. **Held/pressed** — this chip is the one physically down: `background: var(--accent); border-color: var(--accent); box-shadow: 0 0 14px 2px rgb(255 122 26 / .4);` key/name color flips to `--bg-0`. Always wins over echo on the same chip.
2. **Soft echo** — a different pad or chip sharing this chip's key is currently held/latched (source: `displayKeys`, so a latched-but-released key still echoes), and this chip itself is not the one held: `background: rgb(255 122 26 / .18); border-color: var(--accent);` no glow, no text-color flip.
3. **Default/idle** — `background: var(--bg-2); border: 1px solid var(--bg-4);` plus the cream-outline hint (`rgb(244 241 234 / .6)` border) on natural-key chips only.

Other locked interaction rules:
- Per-key hold safety (D-04): releasing a chip never silences a pad still held for that key, and vice versa.
- Unmount-while-held (D-07): a chip that unmounts while its key is held releases immediately and idempotently — triggers are bank change, iPhone panel close (× / strip / Escape), and paging away. This intentionally differs from pads, which persist highlight across a bank change; chips do not, to guarantee no hanging notes.
- Browsing is silent (D-08): open, page, close, and bank-driven re-render emit no MIDI and touch no latch/engine/transport/clock state — the D-07 forced release is the only exception.
- Focus-visible: `outline: 2px solid var(--system); outline-offset: 1px` on the iPhone strip and panel nav buttons (sourced from sketch CSS `.strip:focus-visible, .p-btn:focus-visible`).
