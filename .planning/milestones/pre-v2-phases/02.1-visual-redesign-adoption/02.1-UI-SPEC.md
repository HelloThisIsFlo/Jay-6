# Phase 02.1 - UI Design Contract

> Visual and interaction contract for adopting the committed Jay-6 v3 redesign on the existing v1 UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Lock

| Property | Contract |
|----------|----------|
| Phase goal | Adopt the committed Jay-6 v3 visual redesign for the existing v1 feature set. |
| In scope | App shell, TopBar C2, setup popover, pad surface, per-style variation pickers, retained footer/shortcut affordance. |
| Out of scope | Progression rail, progression authoring, sequencer UI, queued/countdown toast, new playback behavior, new MIDI behavior. |
| Visual baseline | `.planning/sketches/001-jay-6-visual-redesign/01-topbar-c2-recommended.png`, `02-variations-arp-composed.png`, `04-full-mock-v2-recommended.png`, `05-variations-beat-grid.png`, `06-variations-rhythm-gate-tiles.png`. |
| Future-only references | `03-progressions-chip-rail.png` and `07-toast-bottom-center-pill.png` may be viewed only to understand future visual language; do not implement those surfaces in this phase. |

Source: `02.1-SPEC.md`, `02.1-CONTEXT.md`, sketch-findings-jay-6.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none; use text labels, mono readouts, and purpose-built glyphs from existing phrase/rhythm data |
| Font | System UI for prose/labels; `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, monospace` for chord names, BPM, MIDI channel, variation IDs, and symbolic instrument data |

Contracts:

- Use scoped Svelte CSS as the default implementation pattern.
- A small shared token file is allowed only if it reduces duplication across `App.svelte`, `TopBar.svelte`, and `PianoLayout.svelte`.
- Do not add shadcn, Tailwind, Radix, Base UI, or a component library for this phase.
- `components.json`, Tailwind config, and PostCSS config are absent; shadcn registry safety is not applicable.

Source: `02.1-SPEC.md` constraints, `02.1-CONTEXT.md` D-01/D-02, codebase scout.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, label-to-readout spacing, tight internal separations |
| sm | 8px | Compact control gaps, chip padding, pad internal rhythm |
| md | 16px | Default control spacing, TopBar group gaps, popover field grouping |
| lg | 24px | TopBar and shell padding, pad-frame padding |
| xl | 32px | Major vertical gaps between TopBar, pad frame, and footer |
| 2xl | 48px | Wide desktop breathing room around the instrument surface |
| 3xl | 64px | Page-level maximum spacing only; avoid on iPhone landscape |

Exceptions:

- Coarse-pointer tap targets must be at least 44px high/wide for custom buttons and segmented controls.
- Native `select` controls may keep platform sizing; do not force global 44px rules onto native option rendering.
- Radii are not spacing tokens: use 4px, 6px, and 10px only.

Source: sketch token docs, existing iPad touch contract in `TopBar.svelte` and `App.svelte`.

## Typography

Use exactly these four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / Eyebrow | 11px | 600 | 1.2 |
| Body | 14px | 400 | 1.5 |
| Readout / Compact Heading | 18px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Contracts:

- Weights are limited to regular 400 and semibold 600.
- Use uppercase labels sparingly for instrument-panel grouping; letter spacing stays `0`.
- Use mono only for instrument data, not paragraph text.
- Chord labels on pads must stay readable at desktop, iPad, and iPhone-landscape sizes without clipping or overlapping adjacent pads.

Source: `.codex/skills/sketch-findings-jay-6/references/tokens.md`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0e0e0e` | App background and outer instrument chrome |
| Secondary (30%) | `#171717`, `#1f1f1f`, `#2a2a2a`, `#3a3a3a`, `#4a4a4a`, `#000000` | TopBar, setup popover, control faces, hover states, borders/dividers, pad frame |
| Accent (10%) | `#ff7a1a` | Currently sounding or latched pad fill/glow only |
| System status | `oklch(0.68 0.045 250)` and `oklch(0.42 0.04 250 / 0.35)` | Existing secondary system status, external/disabled/read-only emphasis, focus/selection borders where needed |
| Pad surface | `#f4f1ea`, `#2e2e2e` | White/cream pads and black-key pads |
| Destructive | none | No destructive actions in this phase |

Accent reserved for:

- A pad that is physically held and currently sounding.
- A pad sustained by latch and currently sounding.
- Pad glow/border attached to those active pad states.

Accent prohibited for:

- Merely selected variation cells.
- Latch toggle enabled state when no pad is sounding.
- Queued, pending, armed, next, hover, decorative, focus, or setup states.
- Progression/toast/sequencer visuals, because those surfaces are out of scope.

Contracts:

- Selected variation controls use shape, border, contrast, and/or steel system treatment, not solid orange active-pad treatment.
- Disabled/read-only controls remain legible; BPM is visible but read-only under external clock.
- Do not introduce purple, blue, green, or decorative accent palettes.

Source: `02.1-SPEC.md` prohibitions, `02.1-CONTEXT.md` D-03, sketch token docs.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open Setup |
| Empty state heading | No MIDI outputs |
| Empty state body | Connect or enable a Web MIDI device, then open setup again. |
| Error state | MIDI unavailable. Use Chrome or Edge and allow MIDI access. |
| Destructive confirmation | None: no destructive actions are introduced or redesigned in this phase. |

Additional labels:

- Setup status pill closed state must summarize output, input/clock, channel, BPM, and Int/Ext state in compact mono readouts.
- Setup popover field labels are exactly: Output, Input, Channel, Clock, BPM.
- BPM must remain visible in both the pill and setup surface; when clock is external, present it as read-only, not hidden.
- Hold style shows no variation picker.
- Arp styles show direction, octave range, feel, and derived V-number.
- Beat style shows note-value rows and straight/triplet columns.
- Rhythm Gate styles show pattern tiles where the glyph is the primary label.

Source: `02.1-CONTEXT.md` D-04 through D-12, current `TopBar.svelte` control inventory.

## Component And Interaction Contract

| Surface | Contract |
|---------|----------|
| App shell | Reads as a compact hardware instrument surface, not a SaaS dashboard. Keep the UI dense, restrained, and performance-first. |
| TopBar C2 closed state | Single performance-first bar: setup status pill, bank controls, style/variation readout/control, transpose stepper, latch control. |
| Setup popover | Opens from the status pill. Contains Output, Input, Channel, Clock, and BPM. Must be reachable and dismissible on desktop, iPad-sized, and iPhone landscape viewports. |
| MIDI state | Preserve unsupported, requesting, denied, error, no-output, no-input, selected-output, and selected-input visibility. Render device names through Svelte text interpolation only. |
| Clock/BPM | Int/Ext clock remains existing behavior. Ext requires selected input. BPM stays visible and becomes read-only under Ext clock. |
| Bank | Preserve previous/next and direct bank selection for all 100 banks. |
| Transpose | Preserve octave down/up stepping and clamped state. |
| Latch | Preserve existing toggle behavior. Visual enabled state must not look like an active sounding pad unless a pad is actually sounding/latched. |
| Pads | Preserve the existing 5-black/7-white J-6 hardware rows, clean gap, key mapping, pointer capture, release, cancel, lost-capture, and keyboard behavior. Restyle only unless layout wrappers are necessary. |
| Pad held state | Orange fill/glow only for physically held or latched sounding pads. No non-sounding pad may use active orange. |
| Variation pickers | Replace raw numeric dropdown as primary UI. All controls write exact existing `ui.variation` indices through `setVariation()`. |
| Rhythm Gate gate | Gate slider remains available for `rhythm4` and `rhythm5`; absent for Hold, Arp, and Beat styles. |
| Footer/shortcuts | May be retained and restyled quietly. It must not compete with the instrument surface. |

Source: `02.1-SPEC.md`, `02.1-CONTEXT.md`, `TopBar.svelte`, `PianoLayout.svelte`, `App.svelte`.

## Variation Mapping Contract

| Style | Picker Model | Required Mapping |
|-------|--------------|------------------|
| Hold | No variation picker | `STYLE_VARIATION_COUNT.hold === 0`; `ui.variation` remains ignored/reset by existing state path |
| Arp Style 1 | Direction x octave range x feel, derived V-number | Use `style1` metadata; indices 1..12 remain exact |
| Arp Style 2 | Direction x octave range x feel, derived V-number | Use `style2` metadata; indices 1..12 remain exact |
| Beat Style 3 | 6 note-value rows x straight/triplet columns | Use `style3` metadata; straight maps 1..6, triplet maps 7..12 |
| Rhythm Gate Style 4 | 4x3 pattern tiles | Use `style4` metadata; pattern glyphs render from 16-character pattern strings |
| Rhythm Gate Style 5 | 4x3 pattern tiles | Use `style5` metadata; pattern glyphs render from 16-character pattern strings |

Required smoke samples:

- For Arp, Beat, Rhythm Gate 4, and Rhythm Gate 5, verify equivalents for variation `1`, `6`, `7`, and `12`.
- Repeated selections must remain idempotent and immediate; do not introduce queued application, countdown, delayed arming, or new playback timing.
- If mapping helpers become pure TypeScript, add focused Vitest coverage for the mappings.

Source: `src/phrases.ts`, `src/state.svelte.ts`, `02.1-VALIDATION.md`.

## Responsive Contract

| Viewport Class | Contract |
|----------------|----------|
| Desktop | TopBar C2 stays single-row where practical; pad frame is centered and visually dominant; no progression/toast surfaces are present. |
| iPad-sized | Use the stacked two-row TopBar direction below roughly 900px; all setup controls remain reachable; pads remain playable with 44px minimum custom targets. |
| iPhone landscape | Short-viewport scroll escape stays available; no controls or pad rows are trapped off-screen; no incoherent overlap or clipped primary labels. |

Verification viewports:

- Desktop browser viewport.
- iPad-sized browser viewport.
- iPhone-landscape browser viewport.

Contracts:

- Do not rely on pixel-perfect screenshot matching for the missing open-popover state.
- Validate closed TopBar, open setup popover, active pad state, each variation picker family, and Rhythm Gate gate control.
- Preserve the existing short-viewport scroll behavior in `App.svelte`.

Source: `02.1-SPEC.md` R5, `02.1-CONTEXT.md` D-06, `02.1-VALIDATION.md`.
