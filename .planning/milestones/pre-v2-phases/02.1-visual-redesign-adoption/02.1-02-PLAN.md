<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Web MIDI device names -> TopBar text | Browser-provided MIDI names render into the setup UI. |
| User controls -> global UI state | TopBar controls update global state and MIDI selectors. |
| Variation model -> playback engine | Visual picker choices flow through `ui.variation` into the existing EngineHost bridge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-03 | Spoofing | `TopBar.svelte` MIDI status | medium | mitigate | Preserve unsupported/requesting/denied/error/no-output/no-input branches so unavailable MIDI states remain visible. |
| T-02.1-04 | Tampering | `VariationPicker.svelte` -> `setVariation` | medium | mitigate | Task 1 tests exact mapping models and Task 3 requires the picker callback to call `setVariation(index)` without a parallel selected state. |
| T-02.1-05 | Information Disclosure | MIDI device names | low | accept | This is a local browser instrument; device names are already visible to the local user and remain rendered through Svelte interpolation, not raw HTML. |
| T-02.1-SC | Tampering | npm installs | low | accept | No package installs are planned; Plan 02 uses existing Svelte/Vitest stack only. |
</threat_model>
